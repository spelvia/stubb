A release candidate for 0.1.1. Agents' questions, plan approvals, forms and own permission choices reach the host as requests of their own, so it can show them as more than a tool permission. Codex sessions forward requests, and MCP tool calls carry their results.

## Features

- **Explicit skill invocation.** Claude Code, Codex and Pi sessions expose their invocable skills through `Session::skills()`. Pass a returned ID and a regular turn input to `Session::invoke_skill()` to send instructions and images through the provider’s native invocation mechanism. Other adapters inherit the unsupported-operation defaults.

- **Questions.** `request::Kind::Question` carries an agent's questions, each with a header, options with descriptions, and whether several options or the user's own words are allowed. Answer with the new `Decision::Answer` and one `request::Answer` per question: the picked option labels and the user's own words.
  - Claude Code: its `AskUserQuestion` tool. The answers go into the tool's input as Claude Code's own prompt writes them, so the agent reads them; before, allowing the call returned no answers. Question ids are the question text.
  - Codex: `request_user_input`, including secret questions.
- **Plan approval.** `request::Kind::PlanApproval` carries the plan in Markdown, the file it was saved to, and options to approve it with. `Decision::Allow` approves the plan, the new `Decision::Select` approves it with one of its options, and `Decision::Deny` with a message rejects it and gives the agent that feedback.
  - Claude Code: its `ExitPlanMode` tool. The options switch the session's permission mode to `acceptEdits` or `default` as the plan is approved.
- **Forms.** `request::Kind::Form` carries a message and the fields of a flat JSON schema (text, number, integer, boolean, single and multi-select, with titles, formats, bounds and defaults), or a URL to open. Answer with the new `Decision::Submit` and the values by field name, or decline with `Decision::Deny`.
  - Codex: MCP servers' elicitations.
  - ACP: `elicitation/create`, in form and URL mode. Stubb now advertises the `elicitation` client capability.
- **The agent's own permission choices.** `request::Kind::Permission` is a tool permission with the options the agent offers, each with an id, its label and a `request::ChoiceKind` (allow once, allow always, reject once, reject always). Answer with `Decision::Select`.
  - ACP: every permission request. Before, they were `Kind::Tool` and their options were reduced to allow, allow always and reject.
- **Codex forwards requests.** A Codex session started or resumed with `Settings::forward_requests` now forwards command, file-change and permission approvals as `Kind::Tool`, along with questions and MCP elicitations. Before, Stubb declined them in every session; without the setting it still does. A request Codex resolves itself is reported withdrawn.
- Claude Code notebook edits report the notebook path, cell ID, cell type, operation and source through `ToolDetail::NotebookEdit`.
- Claude Code results carrying native cost information emit `Event::TurnAccounting` before the turn ends. Tokens count the turn's calls. The USD amount is the session cost reported by Claude at that point.

- **MCP results.** `turn::ToolDetail::McpCall` carries an MCP tool call with its result, `turn::McpResult`: the content blocks and structured content the server returned. Claude Code, Codex and Pi report MCP calls this way, live and from stored history. Claude Code now also reports the error of a failed MCP call.
- **`Error::InvalidDecision`** reports a decision that does not answer the request, such as an answer to a tool permission or an option the request does not offer. The request stays pending.

- **Agent titles.** `Event::Title` carries a title the agent gave the session, for hosts to show instead of the first message.
  - ACP: `session_info_update` with a title.
  - Codex: `thread/name/updated`, sent when a client renames the thread (`thread/name/set`); Codex does not name threads itself.
  - Claude Code: a `custom-title` entry (`/rename`) or an `ai-title` entry in the session transcript, read after each turn. Claude Code in the stream-json mode Stubb drives writes only `custom-title`.
- **Claude model labels with their version.** Claude Code names a model by its family (`Opus`) and puts the version at the start of the description (`Opus 5.5 · …`). The catalog's label now reads `Opus 5.5` and the description the rest; other descriptions are kept as Claude Code gives them.

- **MCP prompts.** Claude sessions expose provider-owned prompts via `Session::mcp_prompts` and accept positional input through `invoke_mcp_prompt`. With the optional `mcp` feature, hosts can use `mcp::PromptClient` to list prompts and retrieve ordered messages with named arguments over an authorized stdio connection.

## Compatibility

Only additions to the API: the new request kinds, decisions and types, `Event::Title`, `ToolDetail::McpCall` and `Error::InvalidDecision`, and every enum they extend is `#[non_exhaustive]`. The event JSON format stays `EVENT_FORMAT` 1, and events stored by earlier versions read as before.

Some requests and tool calls now arrive in their new shape, which hosts should handle:

- Claude Code's `AskUserQuestion` and `ExitPlanMode` prompts are `Kind::Question` and `Kind::PlanApproval` instead of `Kind::Tool`, and ACP permission requests are `Kind::Permission`. Hosts that answer an unknown kind with `Allow`, `Deny` or `Cancel` keep working: every kind still accepts them as before.
- MCP calls are `ToolDetail::McpCall` instead of `ToolDetail::Mcp`. Stubb no longer reports `Mcp`; it remains so stored events still read.
- Codex sessions with `forward_requests` now wait for the host's answer to approvals instead of having them declined.
- Claude model labels include their version (`Opus 5.5` instead of `Opus`).
- ACP's answer to a decision that matches none of the agent's options is `Error::InvalidDecision` instead of `Error::InvalidSetting`.
