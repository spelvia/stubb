## Breaking changes

This release candidate reorganizes Stubb's public API so the shared interface no longer names individual providers. Code written against 0.1.0-rc.1 needs its imports updated; behavior is unchanged.

- **Providers moved under `stubb::providers`.** Each sits behind a Cargo feature of the same name (`claude`, `codex`, `pi`, `acp`), all enabled by default. Applications can compile only the providers they use, and the Agent Client Protocol dependency is only built with `acp`.
- **Permission settings are provider-neutral.** `permission::Configuration` is now a struct that carries one provider's typed settings, instead of an enum with a variant per provider. Stored settings JSON is unchanged, so settings saved with 0.1.0-rc.1 still load.
- **Built-in agents are described by `discovery::Cli`.** It replaces the fixed `probe::Harness` enum. Each built-in provider exports its `CLI`, and `discovery::clis()` lists those compiled in. Probe reports, update plans and update outcomes name the agent in a `cli` field, which serializes as the provider id.
- **Observation types are grouped under `stubb::observation`.** `agent`, `task` and `control` are now its submodules.

### Upgrading from 0.1.0-rc.1

| 0.1.0-rc.1 | 0.1.0-rc.2 |
| --- | --- |
| `stubb::claude`, `stubb::codex`, `stubb::pi`, `stubb::acp` | `stubb::providers::claude`, `…::codex`, `…::pi`, `…::acp` |
| `stubb::registry` | `stubb::providers::acp::registry` |
| `stubb::probe::{probe, probe_all, Report, Auth}` | `stubb::discovery::{probe, probe_all, Report, Auth}` |
| `stubb::probe::Harness::Codex` | `stubb::providers::codex::CLI` |
| `Harness::ALL` | `stubb::discovery::clis()` |
| `report.harness`, `plan.harness`, `outcome.harness` | `report.cli`, `plan.cli`, `outcome.cli` (JSON field `cli`) |
| `stubb::profile::of(harness)` | `cli.profile()` |
| `stubb::update::package(harness)` | `cli.package()` |
| `stubb::profile`, `stubb::update` | `stubb::discovery::profile`, `stubb::discovery::update` |
| `Configuration::Codex(permissions)` | `permissions.into()` or `Configuration::new(&permissions)` |
| `match` on `Configuration::Codex(p)` | `configuration.get::<codex::Permissions>()?` |
| `EffectiveConfiguration::Codex(p)` | `info.effective.get::<codex::EffectivePermissions>()?` |
| `stubb::agent`, `stubb::task`, `stubb::control` | `stubb::observation::agent`, `…::task`, `…::control` |

## Features

- **Choose providers at compile time** with the `claude`, `codex`, `pi` and `acp` features.
- **A quick-start example**, `examples/quickstart.rs`, streams one Claude Code reply in about 40 lines.
